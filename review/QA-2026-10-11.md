## 입출력·저장·안전성

- 실제 TXT: BOM + `가 A\r\n😀`, **14바이트**, 바이트 전체 기대값과 일치.
- 실제 빈도 CSV: UTF-8 BOM, **2,916바이트**, 150개 전체 항목·횟수·비율·행 순서가 기대값과 일치.
- UTF-8 TXT 불러오기 성공. 잘못된 인코딩은 안내 후 기존 입력 보존.
- 비교 도구에서 TXT를 수정문에 불러올 때 원문이 유지되는 것을 확인.
- 결과 복사 후 클립보드 실제 내용 일치.
- 명시적 결과 전달 후 다음 도구에 정확한 내용이 보이고 URL에 원문이 들어가지 않음.
- 결과 적용 → 작업 되돌리기에서 원문 복원.
- 기본 초안 저장 꺼짐. 켠 뒤 새로고침하면 자동 입력 대신 복원 안내 표시. 복원 후에도 저장은 직접 켜야 함.
- 두 탭에서 같은 도구의 저장을 바꿀 때 다른 탭의 저장이 중단되고 현재 입력 보존.
- 초안 삭제 후 현재 입력 유지. 만료·버전 손상·저장 실패·충돌은 별도 자동 검사 포함.
- 확대 편집 → Escape 종료와 스크롤 잠금 해제 확인.
- 20만 코드 단위 초과 입력은 이전 입력 보존과 오류 안내. 이전 작업 완료가 오류 안내를 덮는 문제를 수정하고 재확인.
- 과도한 치환 결과가 40만 코드 단위를 넘을 때 중단, 원문 보존.
- HTML 태그가 비교 결과에 문자로 표시됨. 결과 영역에 script/img 요소가 생성되지 않음.
- CSP가 적용된 상태에서 계산·Worker 실행·도구 간 전달 정상, 사이트의 콘솔 오류 없음.
- 알 수 없는 로컬 URL은 HTTP 404, 정상 홈은 HTTP 200.

## 화면 점검

- 390px 폭에서 모든 10개 도구의 예제 처리 성공, 문서 전체 가로 넘침 없음.
- 320·768·1920px에서 찾기·바꾸기 화면의 가로 넘침 없음. 1920px에서 공통 헤더 최대 폭 1200px 확인.
- PC 원문/결과 좌우 배치, 모바일 상하 배치.
- 모바일 메뉴 열기 확인. 공통 K 로고·파비콘·카드·푸터·Family Sites 적용.
- 첫 화면의 장식 영역을 줄여 도구 진입을 앞당기고 보조 글자의 색을 진하게 조정.
- 큰 수치의 모바일 배치를 보완해 숫자와 단위를 분리.
- 320px에서 20만 글자 입력·계산 성공, 문서 가로 폭 305px. 계산 기준 표가 부모 그리드를 넓히던 문제를 수정하여 표 영역 안에서만 스크롤되도록 확인.
- 최종 빌드의 390px 화면에서 10개 도구 모두 재검사: 처리 완료, 문서 가로 폭 375px로 넘침 없음.
- 영문 첫 글자 처리에서 아포스트로피와 문장 앞 공백·인용부호의 경계조건을 추가 검사하고 보완.

## 확인 범위의 한계

- 실제 iPhone/Safari·Firefox·Android 및 운영체제 한글 IME를 이용한 수동 검사는 하지 않았습니다. 반응형 점검은 Chromium 화면 폭 변경입니다.
- 한글 조합 중 편집기를 다시 쓰지 않는 코드를 적용했습니다. 실제 기기의 키보드 조합·커서 동작은 추가 수동 확인 대상입니다.
- 외부 맞춤법 검사기는 링크로만 제공하며 외부 서비스의 검사 결과를 검증한 것은 아닙니다.
- HTTPS·DNS·실제 Cloudflare의 헤더·맞춤 404·검색 로봇 접근은 배포 후 확인해야 합니다.
- AdSense 연결·광고 심사·검색엔진 등록과 실제 색인/순위는 이번 로컬 개발 범위에 포함되지 않습니다.
